# Lossless Mosaic · 可逆马赛克

Rust + Tauri 2 + TypeScript 本地图形客户端。用密码派生等长密钥流，与 BMP 指定网格逐字节 XOR，再用相同密码完整还原。文件和密码不上传。

## 启动与构建

需要 Node.js 22.12+、npm、Rust stable 与 [Tauri 系统依赖](https://v2.tauri.app/start/prerequisites/)。macOS 需要 Xcode Command Line Tools。

```sh
npm ci
npm run desktop
```

```sh
npm run tauri build
# target/release/bundle/macos/Lossless Mosaic.app
```

`npm run dev` 只预览界面；完整文件操作需要桌面客户端。当前验证平台为 macOS，Windows/Linux 安装包及实机兼容性尚未验证。

## 像素笔刷与区块笔刷

1. 打开未压缩的 24/32 位 Windows BMP：BI_RGB，DIB 头 40/108/124 字节，最大 64 MiB、1600 万像素。
2. 推荐顺序为 **α 通道 → 整区块 → 附加文件**，默认 α。只有区块模式按 8 / 16 / 32 / 64 像素划分网格，越小越密。
3. α 和附加文件模式使用像素精度的圆形笔刷，直径 1–256 px，可涂抹或擦除单个像素，不吸附网格。区块模式笔刷宽度 1–8 格，轨迹经过整格即选中或移除。重复、重叠操作覆盖旧状态，不会反复 XOR。
4. 输入并确认密码，点击「应用打码 / 反打码」，再另存为。蒙版修改在应用前不会改变文件，未应用时禁止直接保存，保存须使用新文件名。
5. 已应用的结果可以继续涂抹、擦除、重划网格，再用原密码应用。α 和附加文件模式重新打开后会加载已有蒙版。撤销按完整笔触记录，支持反打码、清空、网格尺寸切换及重做。
6. 「密码还原」用于完整还原 α / 附加文件载体。附加文件自动读取相邻的 `文件名.bmp.lmm`，也可手动导入。局部还原则在「编辑打码」中用反打码笔刷移除对应网格并应用。
7. 零附加数据的区块图片重新打开后，需选整区块模式和加密时相同的区块尺寸。使用「熵检测建议」并手动修正，再到「密码还原」应用。要继续编辑已有区块，先标记全部现有加密网格，点击「将当前网格记作已有打码」，再涂抹、擦除并用原密码应用。此模式无法验证判断或密码。

只有区块模式切换到更粗的网格时，所有与旧选区相交的新网格才会被选中。α 和附加文件模式始终保留像素精度，旧 v1 矩形载体继续编辑时也保留原像素边界。切换模式时，只有转入区块模式才扩展到相交网格。

## 缩放与平移

预览提供放大、缩小、适应画布和 1:1。滚轮平移，Ctrl/⌘ + 滚轮围绕指针缩放，空格或中键拖动临时平移；也可以选择「平移」工具。

手动缩放范围 1%–1600%，适应画布可小于 1%。预览使用原分辨率 PNG，1:1 或放大后可以查看实际像素；笔刷通过逆变换定位原图坐标。

快捷键：⌘/Ctrl+O 打开，⌘/Ctrl+S 保存，⌘/Ctrl+Z 撤销，⌘/Ctrl+Shift+Z 重做，Esc 取消当前笔触，[ / ] 调笔刷宽度，+ / − 缩放，0 适应。

## 三种模式

| 推荐顺序          | 分发方式                          | 加密通道 | 还原保证与限制                                                                |
| ----------------- | --------------------------------- | -------- | ----------------------------------------------------------------------------- |
| 1. α 通道（默认） | 还原信息与蒙版在 α 内，单文件分发 | BGR      | 24 位输入逐字节还原；32 位输入需确认覆盖原 α，还原后 α 为 255；容量不足时拒绝 |
| 2. 整区块         | 零附加数据、零标签                | BGR(A)   | 相同密码、尺寸、位深、网格尺寸及位置可逐字节还原；无法检测错密码，熵可能误判  |
| 3. 附加文件       | BMP 与 `.bmp.lmm` 须一起分发      | BGR(A)   | 完整 BMP 逐字节还原，检测错密码与文件篡改；丢失附加文件则无法还原             |

α 载体可能被其他软件显示为异常透明度；本软件统一显示不透明 RGB。不要裁剪、重采样、转码打码文件，应通过原文件传输。32 位 α 模式丢弃的原透明度无法通过后续编辑找回。

## 密码与 XOR

- Argon2id v1.3：64 MiB、3 次迭代、1 lane，派生 256 位种子。XChaCha20 生成等长密钥流，逐字节 XOR，不是重复使用短密码。
- α / 附加文件模式使用 XChaCha20-Poly1305，随机 16 字节盐与 24 字节 nonce。v2 将选中网格拼接后统一加密认证，元数据和完整载体哈希同样受认证保护。
- 零附加数据区块模式无法保存随机盐和 nonce，故从图片几何信息及网格坐标确定参数。同密码、同尺寸、同位深、同位置会复用密钥流；两个密文 XOR 会暴露两个明文的 XOR。每张图片应使用独特密码；需要随机化与认证时使用 α 或附加文件模式。
- 短密码仍可能被穷举，密钥扩展不会增加密码本身的熵。Rust 密钥和命令侧密码缓冲使用 zeroize，JavaScript/IPC 临时副本无法保证完全擦除。区块编辑会话在内存中持有恢复出的源文件，不写临时明文文件。

算法依据：[Argon2 RustCrypto](https://docs.rs/argon2/0.5.3/argon2/)、[XChaCha20-Poly1305 RustCrypto](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/)。项目尚未进行独立密码学安全审计。

## 工程结构

```text
crates/mosaic-core/       独立核心，无 Tauri、文件系统或网络依赖
  src/domain.rs          领域值对象和错误
  src/selection.rs       网格尺寸、位图、边界约束
  src/application.rs     打码、还原、完整性与熵建议用例
  src/bmp.rs             BMP 适配与非像素字节保留
  src/crypto.rs          KDF、流 XOR、认证密码原语
  src/envelope.rs        有版本的载体协议
src-tauri/src/main.rs    原生对话框、会话、后台任务与另存为
src/grid.ts              纯交互模型：连续笔刷、蒙版、重划网格
src/viewport.ts          纯坐标模型：缩放、平移、坐标逆变换
src/main.ts              界面与 IPC
```

采用轻量 DDD，用例组合纯内存操作，桌面适配器只调用核心公开 API，不为单一 BMP 适配器提前引入泛化 Repository。详见[架构说明](docs/architecture.md)。
