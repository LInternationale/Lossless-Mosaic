# Lossless Mosaic · 可逆马赛克

使用 **Rust + Tauri 2 + TypeScript** 的本地图形客户端，为 BMP 的指定区域打码，并用相同密码还原。像素数据与密钥流逐字节 **XOR**，加密后呈现噪声式遮挡。图片和密码不上传。

## 启动

需要 Node.js 22.12+、npm、Rust stable 与对应平台的 [Tauri 系统依赖](https://v2.tauri.app/start/prerequisites/)。macOS 需要 Xcode Command Line Tools。

```sh
npm ci
npm run desktop
```

生成可独立启动的 macOS 客户端：

```sh
npm run tauri build
# target/release/bundle/macos/Lossless Mosaic.app
```

`npm run dev` 仅预览界面，完整文件操作与密码处理需要桌面客户端。当前 bundle 配置生成 macOS `.app`；Windows/Linux 的安装包与实机兼容性尚未验证。

## 使用

1. 打开未压缩的 24/32 位 Windows BMP（BI_RGB，DIB 头 40/108/124 字节）。上限 64 MiB、1600 万像素。
2. 选择模式，在画布拖动添加不重叠矩形选区；普通模式最多 256 个。可撤销、清空或点击选区条目移除。
3. 输入并确认密码，点击「加密选区」，再「另存为」。保存必须使用新文件名，避免覆盖原图。
4. 还原时打开打码图片并切换到「密码还原」。附加数据模式会自动读取旁边的 `文件名.bmp.lmm`，也可以手动导入。
5. 区块模式需要手动选择该模式。点击「熵检测建议」，检查建议结果：点击网格可增删，拖动可批量添加，然后输入密码还原所选块。边缘不足 32 像素的网格按实际大小处理。

快捷键：⌘/Ctrl+O 打开，⌘/Ctrl+S 另存为，⌘/Ctrl+Z 撤销最后一个选区，Esc 取消正在拖动的选区。

## 三种可选模式

| 模式             | 标记 / 还原信息                                          | 加密通道           | 还原保证与限制                                                                                                                                          |
| ---------------- | -------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 附加数据（推荐） | 独立 `.bmp.lmm` 文件，保存盐、随机 nonce、坐标和认证信息 | BGR，32 位时包括 α | BMP 全文件逐字节还原；丢失还原文件则不能还原；密码错误或文件修改会被拒绝                                                                                |
| α 通道           | 将还原信息写入整幅图的 α 字节                            | BGR                | 24 位输入转换为 32 位载体，记录原头、填充和尾部，最终逐字节还原；32 位输入会覆盖原 α，需勾选警告，恢复后 α 全部为 255，原透明度不可还原；容量不足会拒绝 |
| 整区块（实验性） | **不附加任何数据，不写标签，不占用 α**；熵建议与手动选块 | BGR，32 位时包括 α | 同密码、同尺寸、同位深、同位置区块可逐字节还原；错误密码或选块无法自动验证；原噪声图可能被误判                                                          |

α 载体的元数据可能被其他软件显示为异常透明度；本软件预览按不透明 RGB 显示。不要重采样、裁剪、转码或通过会重编码的图片分享功能传递打码文件。应以原文件传输。首版不支持在 α / 附加数据模式中叠加加密已有载体，先还原再编辑。

## 密码与 XOR

- Argon2id v1.3：64 MiB 内存、3 次迭代、1 lane，派生 256 位种子密钥。
- XChaCha20 从种子生成等长密钥流，以 XOR 变换所选数据，不是简单重复短密码。
- α / 附加数据模式使用 XChaCha20-Poly1305（内部为流 XOR + 认证），每次生成随机 16 字节盐、每区域独立 24 字节 nonce，并认证元数据与完整载体哈希。它们可检测错误密码及文件篡改。
- **零附加数据的区块模式无法保存随机盐或 nonce**，故从尺寸/位深确定盐、从固定网格坐标确定 nonce。相同密码、尺寸、位深与位置会复用密钥流，两个密文 XOR 会暴露两个明文的 XOR。此模式满足零附加数据和手选需求，**不具备随机化加密模式的安全性**。为每张图片使用独特密码；需要更强保护时用附加数据模式。
- 短密码仍可能被穷举。密钥扩展不会凭空增加密码的熵。Rust 派生密钥和命令侧密码缓冲使用 zeroize；JavaScript/IPC 的临时副本无法保证完全擦除。

算法依据：[Argon2 RustCrypto](https://docs.rs/argon2/0.5.3/argon2/)、[XChaCha20-Poly1305 RustCrypto](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/)。尚未进行独立密码学安全审计。

## 工程结构

```text
crates/mosaic-core/       独立领域与用例库，无 Tauri、文件系统、网络依赖
  src/domain.rs          Rect、Mode、约束与领域错误
  src/application.rs     打码、还原、熵建议与完整性规则
  src/bmp.rs             严格 BMP 适配、坐标与原始字节保留
  src/crypto.rs          KDF、随机数、流 XOR 和认证密码原语
  src/envelope.rs        有版本的还原信息格式与认证
src-tauri/src/main.rs    原生文件对话框、会话、后台任务与安全另存为
src/                     TypeScript 图形客户端，画布坐标映射与手动网格选区
```

采用轻量 DDD：领域值对象表达约束，用例组合纯内存操作；桌面层作为应用适配器，仅通过核心库的公开 API 交互。没有为单一 BMP 适配器引入多余的 Repository/服务接口。边界与数据协议见 [架构说明](docs/architecture.md)。

## 验证

```sh
cargo test -p mosaic-core
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
npm run build
npm run format:check
```

测试覆盖 24/32 位、正/负高度、文件头/填充/尾部完整保留、α 破坏性规则、RGBα 加密范围、零附加区块还原、熵建议、错密码、篡改、随机参数、非法输入。测试比较完整原始字节，而不是只比较显示效果。

可用 `python3 scripts/make_sample.py` 生成 `artifacts/sample.bmp` 体验（仅生成合成图像，无个人数据）。
