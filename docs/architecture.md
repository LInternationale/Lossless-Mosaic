# 领域、用例与文件协议

## 边界

核心库以 `Bitmap`（受约束的文件数据）、`Rect` 和 `Mode` 建模。`protect`、`restore`、`transform_blocks`、`inspect` 是桌面层唯一使用的用例接口。它们接收借用字节与密码，返回新的字节，不操作外部资源，失败时调用者原始数据不变。

`domain` 不依赖其他项目模块。`bmp`、`crypto`、`envelope` 依赖领域类型；`envelope` 使用密码适配器认证自己的格式。`application` 组合它们。所有适配器模块在 crate 外私有，桌面层无法直接调用密码原语。当前使用具体适配器，未来新增格式或 KDF 时，先明确扩展点再引入端口，避免提前泛化。

桌面层持有单文档会话，只有原生对话框可以提供读写路径，前端不能通过任意字符串路径访问文件。阻塞文件对话框、KDF、加解密及图像预览都放在后台任务。结果只有成功生成、通过解析后才替换会话。保存使用 `create_new`，失败不覆盖既有文件；附加文件写入失败则清理本次新建 BMP。双文件保存不是文件系统事务，异常断电仍可能只留下其中一份。用户必须保留两份文件。

前端仅处理 UI 状态、矩形框选、网格确认、缩略预览与 IPC 参数，不实现另一套密码或 BMP 写入算法。预览最长边 1600 像素，选区坐标始终对应原始分辨率。图像 α 仅为存储/加密目的使用，编辑器统一显示不透明 RGB。

## 还原契约

1. **附加数据**：所有选区的 BGR(A) 字节用认证流密码加密，其他字节（含 padding/尾部）不改变。还原后完整文件 SHA-256 应等于原文件哈希。
2. **α / 24 位**：输出一个 top-down、32 位 BI_RGB 载体。α 存储版本信息、原始 BMP 非 BGR 字节骨架和认证信息。解码用 RGB 重建原文件，包含方向、头、扩展、填充和尾部，并校验原文件哈希。
3. **α / 32 位**：α 整体作为可破坏载体，不保存原 α；还原结果保留原文件结构、BGR、填充、尾部，但 α 全为 255。认证原图哈希基于此归一化结果。此模式必须向用户警告并勾选确认。
4. **零附加区块**：32×32 网格锚定左上角，边缘网格截断。选区覆盖到的完整网格只处理一次，包括重叠选区。原始文件长度、所有非像素字节保持不变，XOR 包含 α。无标记、无认证、无哈希，正确密码与相同网格再次 XOR 可恢复所有字节。熵仅为候选建议，用户可自由更正。

## v1 载体格式

α / 附加数据模式的 manifest 是有版本、拒绝未知字段的 JSON，字段顺序由 Rust struct 确定。固定参数 Argon2id，不从外部元数据读取可放大资源用量的 KDF 参数。

```text
Manifest {
  version: 1,
  mode: alpha | sidecar,
  salt: 16 bytes,
  original_len,
  original_hash: SHA256,
  protected_hash: SHA256,
  skeleton: bytes (仅 α / 24 位),
  records: [{ rect, nonce: 24 bytes, tag: 16 bytes }],
  auth_nonce: 24 bytes,
  auth_tag: 16 bytes
}
```

记录的 AAD 为 `lossless-mosaic/v1/{RustModeName}/{x},{y},{width},{height}`，枚举格式名称（Alpha/Sidecar/Entropy）属于 v1 格式的一部分，不可无版本变更地修改。元数据认证时把 `auth_tag` 置零，将规范序列化 JSON 作为 AAD，空消息执行 AEAD。认证 nonce 独立随机生成。完整载体 SHA-256 被上述认证保护，以检测选区外修改。α 模式的 protected hash 在全 α 置零时计算；解码提取 manifest 后也先把全 α 清零。

- 附加文件：`manifest JSON || JSON 长度(u64 LE) || LMMASK01(8 bytes)`。
- α：按逻辑从左至右、从上至下取 α，存为 `LMMASK01 || JSON 长度(u64 LE) || manifest JSON`，剩余 α 全零。
- 区块：没有文件协议附加字段。盐是 `SHA256("lossless-mosaic/blocks/v1/{width}/{height}/{bpp}")[0..16]`，每格 nonce 是 `SHA256(AAD(Entropy, rect))[0..24]`；每格从密钥流偏移 0 开始 XOR。网格大小 32 为 v1 协议常量。

## 资源与失败策略

BMP 限制 64 MiB、1600 万像素、BI_RGB、24/32 位以及 40/108/124 字节 DIB。检查正宽度、非零且非 i32::MIN 高度、单 plane、像素偏移、行步幅和实际文件长度。允许 bfSize 不准确、保留尾部数据，这是为了尽量原样往返而不是重编码。

认证模式最多 256 个非重叠区域。manifest 输入限制 16 MiB，拒绝未知字段、未知版本与错误模式。随机数生成使用系统随机数，失败向上传播。α 容量不足直接拒绝，不截断。区域错误、认证失败及格式错误都有独立中文错误。

熵对每个网格的 BGR 计算 Shannon entropy，阈值为 7.6 bit/byte。细小边缘块样本少，可能漏报；原始高频纹理也可能误报。检测结果不持久化，算法不决定解码正确性。区块模式无法检测重复加密、错误密码、被修改的图片或错选区块。数据已修改时不能承诺完整还原。

## 后续可扩展方向

优先增加大图分块内存处理、用户取消 KDF、刷选/缩放、跨平台实机验证和安全审计。支持 BI_BITFIELDS、压缩 BMP 或其他格式时需定义各自的逐字节还原契约；不能简单转码后沿用当前“原文件完全还原”的表述。
